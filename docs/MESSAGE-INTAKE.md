# 문자 붙여넣기 등록 계약

ADMIN/USER는 인증 후 `POST /api/message-intake/preview`에 `{ "message": "가상 문자 한 건" }`을 전송한다. 규칙 기반 파서이며 모델 호출·DB 변경이 없다. 응답은 `parsed`(kind/status/eligible/title/fields/warnings), `observations`, `existingIncidentId`, `suggestedAssetId`, `matchReason`이다.

`POST /api/message-intake/register`는 `message`, `assetId`, `mode`(REAL/DEMO), `provider`(LOCAL/TYPESAFE/MOCK)를 받는다. 서버가 다시 파싱하여 END_OK/확인 보류 알림을 거부한다. 구성요소는 실제 카탈로그의 비-SYSTEM 항목이어야 한다. 일반 사용자의 초기 담당자는 로그인 계정에서, 관리자는 선택 자산에서 가져오며 이후 Jev 부서 추천과 기존 권한 정책을 따른다.

응답 `{ "id": "INC-…", "duplicate": false }` 후 기존 Jev/Ontology/A2A/Hermes/Harness 흐름을 비동기로 시작한다. HTTP 응답은 분석 완료가 아니라 접수 완료다. SMS만으로 원인·심각도를 확정하지 않으며 기존 담당자 검토와 대응 승인 단계를 유지한다. 복구 지표는 기존 가상 시나리오 지표이며 문자 관측의 실제 복구 측정으로 해석하지 않는다.

## 지원 형식

- 배치: `[운영]END_OK|ABEND: ID 이름 YYYYMMDD YYYY-MM-DD HH:mm:ss`. `[배치ID]`, `[배치명]` 라벨은 선택이다. END_OK는 미등록 정상 알림이다.
- 지연: `[운영]DELAY_END: ID 이름 YYYYMMDD MUST BE END BY HH:mm!`. 종료기한과 업무일자만 저장하며 발생일시를 만들어 넣지 않는다.
- TMS: 임계치 알림의 IF아이디/IF명/업무코드/서비스코드/거래일자/거래시간/메시지 발생일시/현재 건수·오류율/임계치를 필수로 검사한다. 나머지 인식 항목은 있으면 보관한다. 중첩 IF명의 내부 괄호는 보존한다. 현재 오류율은 건수 대비 ±0.02%p 반올림 오차 이내, 오류 건수≤거래 건수, 비율 0~100을 검사한다. 보고된 비교기간 평균은 다시 계산해 덮어쓰지 않는다.
- 날짜/시간은 엄격 검증한다. 입력 시각은 KST이며 서버 등록 시각과 별개다. 잘린 이름은 그대로 보존하고 경고한다. 알 수 없는 형식·누락·여러 문자·반복 필드는 등록하지 않는다.

## 저장·중복·권한

Flyway V6의 `message_intakes`에는 인식된 허용 필드 JSON, 출처 코드, 장애 FK, 등록 행위자, 서버 시각, SHA-256 이벤트 식별자를 저장한다. 원문·발신 기관 헤더·수신자 목록은 보관하지 않으며 AI 관측에도 전달하지 않는다. 사용자가 다른 자유 텍스트 필드에 개인정보를 섞은 경우까지 자동 익명화하지 않으므로 가상·비식별 데이터만 사용한다.

이벤트 식별자는 배치 코드+상태+업무일자+발생일시(지연은 종료기한), TMS IF/서비스 코드+상태+거래일자+메시지 발생일시다. 수신자·공백 차이는 같은 알림이다. 동일 식별자의 수치가 수정되어 재전송되어도 기존 장애를 반환하며 기존 관측을 덮어쓰지 않는다. DELAY_END는 같은 업무일자·코드·기한에 대한 재알림을 한 건으로 본다. 새 이벤트를 구별할 발생 시각이 없기 때문이다.

장애·가상 지표·추출값·감사/이벤트는 한 트랜잭션에서 저장하고 커밋 이후 AI 분석을 시작한다. DB unique 제약으로 중복을 막고 `{ duplicate: true }`로 기존 장애를 반환한다. 중복 요청은 AI 분석을 재실행하지 않는다. 선택 자산 추천은 이전 등록의 확인된 코드 연결만 사용하며, 같은 코드가 여러 자산에 등록되어 있으면 자동 추천하지 않는다.

실제 통신사 SMS API, 휴대폰 백그라운드 수신, 발신번호 인증, 메시지 전달 Webhook은 이번 기능 범위에 포함하지 않는다.
