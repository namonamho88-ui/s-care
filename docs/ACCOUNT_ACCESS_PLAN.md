# 개인 계정과 권한 구현 계획

목표: 공유 관리자 토큰으로만 접속하던 시연을 개인 계정 로그인으로 확장한다. 기존 Jev/Ontology/A2A/Hermes/Harness 흐름과 가상 데이터 제약은 유지한다.

1. PostgreSQL `brain` 스키마에 계정, 서버 세션, 1회용 초대 해시를 추가한다. 기존 테이블과 장애 기록은 삭제하지 않는다. 로컬 H2에서도 같은 Flyway 마이그레이션을 검증한다.
2. 관리자가 가상 담당자와 연결한 계정을 만들고 24시간 유효한 초대 코드를 발급한다. 수신자는 아이디·코드·새 비밀번호로 활성화한다. 이메일 자동 발송은 하지 않는다. 코드 재발급은 기존 비밀번호와 세션을 폐기한다.
3. 비밀번호는 무작위 salt와 PBKDF2-HMAC-SHA256 600,000회로 해시한다. 세션·초대 코드는 256비트 난수이며 DB에는 SHA-256 해시만 저장한다. 세션 만료는 8시간이다. 인증 시도 횟수 제한과 계정 잠금을 적용한다.
4. Spring Boot에서 기본 거부 방식으로 경로와 역할을 검사한다. USER는 조회, 장애 등록, 본인 담당 장애의 후기·예방 대책만 수정한다. ADMIN은 승인·검토·종료·지식 승인·평가·계정 관리를 수행한다. A2A/MCP 직접 호출은 기존 서버 토큰만 허용한다.
5. Next.js는 세션 비밀을 HttpOnly/SameSite 쿠키에 보관하고 응답 JSON에 반환하지 않는다. 로그인, 초대 활성화, 내 비밀번호 변경, 관리자 계정 관리 화면을 구현한다. 관리자 토큰은 초기 설정·복구용 별도 탭에 유지한다.
6. 실제 DB 권한 차단, 초대 재사용·만료, 비활성화·로그아웃·비밀번호 변경 후 세션 폐기, 감사 행위자, 타 담당 장애 수정 금지와 프론트 UI 회귀를 자동 테스트한다. 배포 후 기존 장애를 변경하지 않는 조회와 별도 가상 검증 계정으로 확인한다.

전체 완료로 간주하지 않는 범위: 기업 SSO/MFA, 메일 초대 전달, 고가용성·대규모 부하 검증, 외부 보안 인증, 미보유 TypeSafe API 키를 사용한 실제 호출. 계정 도입 자체가 금융 운영환경 인증을 의미하지 않는다.
