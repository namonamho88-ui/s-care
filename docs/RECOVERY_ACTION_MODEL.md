# 장애 유형별 가상 조치 및 검증

이 기능은 규칙 기반 합성 시뮬레이터다. 실제 명령 실행·운영 배치 재기동·DB 수정은 하지 않는다. LLM이 실제 환경을 복구한 결과로 소개하지 않는다.

## 문자 → 계획 → 승인 → 실행 → 검증

배치 문자 끝에 `오류코드: ORA-00060 오류내용: deadlock detected` 같은 오류 항목을 붙일 수 있다. 기존 ABEND/DELAY_END/END_OK 형식은 유지한다. 수신자·이메일·대표적인 비밀 값은 오류 상세에서 제외한다. 전체 원문을 저장하지 않는다. 직접 입력과 추가 근거에도 가상·비민감 정보만 사용한다.

배치명은 업무 기능 이름이므로 원인 근거에서 제외한다. ABEND/DELAY_END만으로 원인을 확정하지 않는다. 승인 전에 규칙 선택 근거와 예정 조치를 표시한다. 담당자 승인 이후에만 선택한 모델을 실행한다.

| 시나리오 | 대표 근거 | 합성 상태 조치 | 검증 |
|---|---|---|---|
| 입력 파일 누락 | file not found, 입력 파일 누락 | 합성 입력 복원·형식 확인 | 파일 준비, 재실행 및 대사 |
| 권한 부족 | permission denied, ORA-01031 | 합성 필수 권한 복원 | 접근 가능, 재실행 및 대사 |
| 잠금·교착 | ORA-00060, ORA-00054, lock wait | 합성 차단 트랜잭션 롤백 | 차단 건수 0 |
| DB 연결 | ORA-12541, ORA-12514, ORA-12170 | 합성 연결 경로·풀 복구 | DB 연결 정상 |
| 메모리 부족 | heap space, OutOfMemory | 청크 축소·합성 자원 재배치 | 메모리 80% 미만 |
| 디스크 부족 | no space left, ORA-01653 | 합성 임시 공간 확보 | 여유 1024MB 이상 |
| 중복 실행·키 | ORA-00001, already running | 합성 중복 차단·미처리 키 선별 | 중복 0, 멱등키 처리 |
| 데이터 불일치 | 금액/건수 불일치, ORA-01722 | 합성 오류 레코드 격리·검증된 합성 대체 데이터 | 건수·금액 일치, 미해결 0 |
| 선행 작업 실패 | upstream failed, 선행 작업 미완료 | 합성 선행 작업 복구 | 선행 완료 |
| 시간 초과 | timeout, 시간 초과 | 처리 구간 분할 | 청크 60초 이내 |

원인 하나가 식별된 배치는 사전점검 → 원인별 가상 조치 → 멱등키 기반 합성 레코드 처리 → 건수·금액·중복·미해결 레코드 대사로 진행한다. 초기 조건은 1,000개 합성 레코드, 레코드당 합성 금액 10,000, 기처리 체크포인트 984개다. 재실행은 레코드 키를 순회하여 이미 처리한 키를 건너뛰고 실제 처리된 키 집합의 크기와 금액 합을 계산한다. 이 값들은 문자에서 관측된 수치가 아니며 화면에 명시한다.

모르는 오류·복합 원인은 실행 계획을 비워 두고 대응 승인을 서버에서 차단한다. 승인 대기 화면에서 관리자가 추가 오류 근거와 확인 사유를 입력하면 계획을 다시 만든다. 서로 다른 원인을 임의의 우선순위로 덮어쓰지 않는다. `lock wait timeout` 또는 연결 오류의 timeout은 구체적인 잠금/연결 원인의 증상으로 취급한다. 지원 목록은 모든 배치 오류를 포괄하지 않는다.

비배치는 담당자 확인을 거친 RESOURCE/DATABASE/NETWORK/APPLICATION/SECURITY 유형에 따라 서로 다른 합성 상태를 변경하고 서비스 지표를 검증한다.

## 저장과 호환성

기존 events/audit/simulated_metrics JSON에 버전 2 계획, 단계별 전후 상태, 검증 기대값·실제값·통과 여부를 기록한다. 스키마 변경이나 기존 기록 재작성은 없다. 적용 완료 재호출은 저장된 실행 증적을 반환한다. 중단·삭제·승인 통제를 유지한다. 실패 검증 증적을 저장한 뒤 실패를 반환하며 복구 완료로 전환하지 않는다.

승인 전·가상 복구·조치 후기 화면에 실행 증적을 표시하고 PDF/Excel과 한국어 후기 초안에 연결한다. 사용자가 후기를 편집해도 원본 실행 증적은 이벤트·감사 기록에 남는다. 과거 지표 전용 이력에는 조치를 새로 지어내지 않고 '구체적인 조치 과정 미기록'으로 표시한다.

## 한계

오류 코드와 문구를 매칭하는 규칙 모델이며 실제 원인 확정·실운영 복구 검증·완전한 디지털 트윈이 아니다. 숫자·상태 변화는 합성 모델의 전제를 검증한다. 오류 문자열의 부정 표현·여러 로그의 인과관계를 모두 해석하지 않는다. 원인별 운영 절차는 담당자가 별도로 검토해야 한다. 외부 AI 호출은 추가하지 않는다.
