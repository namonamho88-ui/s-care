# 목록 페이징

장애 이력, 해결 Skill, 대응 매뉴얼, Harness 평가, 감사 로그, 등록 계정은 최대 10건씩 표시한다. 목록마다 독립된 현재 페이지와 총 건수·표시 범위를 제공한다. 장애 검색/필터 변경 시 첫 페이지로 돌아가며, 데이터 수가 줄면 마지막 유효 페이지로 보정한다. 페이지 이동은 조회이며 장애 승인·수정·평가 실행을 하지 않는다.

장애 이력/스킬/매뉴얼/계정은 기존에 조회한 목록을 화면에서 나눈다. 이 변경이 모든 목록의 네트워크·DB 조회량을 10건으로 제한하는 것은 아니다. 통합 관제의 최근 6건, 집계 수치, 온톨로지 장애 선택, Skill 승인 전체 건수는 기존 전체 데이터 기준을 유지한다.

## 서버 조회

관리자 전용 `GET /api/evaluations?page=1` 및 `GET /api/audit?page=1`은 다음 구조를 반환한다:

```json
{"items":[],"page":1,"pageSize":10,"total":0}
```

평가는 모든 페이지를 대상으로 계산한 `running` boolean도 반환한다. 다른 페이지에 RUNNING 평가가 있어도 새 실행 버튼을 비활성화하며 기존 서버 실행 제한도 유지한다. 새 평가 접수 후 첫 페이지로 이동한다.

- 페이지는 1부터 시작한다. 0·음수·잘못된 숫자는 400이다. 범위 초과는 마지막 유효 페이지로 보정한다. 0건이면 page=1/items=[]이다.
- SQL `COUNT`, `LIMIT 10 OFFSET`을 사용한다. 평가 정렬은 created_at DESC, id DESC로 동률에서도 결정적이며 감사는 id DESC다. 조회 중 새 기록이 추가되면 페이지 경계는 갱신될 수 있다.
- page가 없는 기존 API는 이전 배열 계약과 최근 평가 20건/감사 300건 제한을 유지한다. 새 UI는 page 계약을 사용하여 전체 기록에 접근한다.
- 미인증 401/일반 사용자 403은 페이지와 무관하게 유지한다. UI는 Harness 메뉴가 열려 있을 때 해당 두 목록만 5초 간격으로 갱신하며 동시에 같은 요청을 중첩하지 않는다. 이전 페이지의 지연 응답은 새 페이지를 덮어쓰지 않는다.
- 실패 시 마지막 성공 페이지와 오류를 표시하고 다시 조회할 수 있다. 페이지 이동 중 버튼을 잠가 요청을 중복시키지 않는다.
