# 모바일 시스템 캠퍼스

`/war-room`은 소스 구성에 근거한 브라우저 전용 운영 시뮬레이터다. 실제 운영 인프라의 디지털 복제나 실측 장애 예측 모델은 아니다. 모든 자산·장애·관측 지표는 가상이다.

## 기존 기능과 경로

- `/war-room`: 개방형 아이소메트릭 지도, 2D 구조도, 목록, 독립 장애 실험.
- `/war-room/classic`: 기존 공동 워룸, 채팅, 캐릭터, 관리자 승인, 서버 트윈 상태를 그대로 유지한다.
- `/war-room/city`: 기존 공동 미션을 유지한다.
- `/?view=twin`: 기존 트윈 실험실을 유지한다.
- 유효한 기존 `/war-room?room=...` 공유 링크는 classic 경로로 연결한다.

캠퍼스는 실험·복구 API, WebSocket 명령, SSH, shell을 호출하지 않는다. 실험 복구 승인 체크는 브라우저 실험의 주입 해제 동의이며 서버 관리자 권한이 아니다. 기존 워룸의 승인 검사는 변경하지 않는다. 새로고침 시 실험은 초기화되며 JSON으로 결과·정책·최대 영향·시간 기록을 내보낼 수 있다.

## 확인한 구성 (기준 main 9a3b9bf)

| 요소 | 근거 | 표현 |
| --- | --- | --- |
| Next.js / BFF / Spring Boot | `frontend/app/page.tsx`, `frontend/app/api/[...path]/route.ts`, `compose.yaml` | 요청 경로 |
| PostgreSQL | `application.yml`, `compose.yaml`, `Store.java` | 장애·자산·승인·지식·보고의 원본 |
| Neo4j | `Ontology.java` | 의존 관계 투영 / 역방향 탐색 |
| DB 작업 큐 | `DurableQueue.java` | PostgreSQL work_jobs와 같은 JVM의 작업 실행기 |
| Jev / Hermes | `JevRouter.java`, `HttpHermesAdapter.java` | 기본 REAL/LOCAL 구성의 선택적 모델 연동 |
| 사용자 기능 | 접수·분석, 영향 분석, 지식 초안, 이력·보고 구현 | 논리 기능 노드. 별도 서비스 인스턴스 수 아님 |

기존 `TwinEngine.java`의 Redis·복제 DB·웹/앱 풀은 합성 금융 시스템 토폴로지다. 캠퍼스에서 이를 S-CARE의 배포 사실로 재사용하지 않는다. 캐시 적중률, 인스턴스 이중화, 독립 Kafka/RabbitMQ, 실제 클라우드 자원 수는 미확인이다. DB 스키마의 가상 금융사 자산과 S-CARE 애플리케이션 자체의 구성을 혼동하지 않는다.

## 모델 교체 지점

`frontend/components/war-room/campus-model.ts`의 `components`, `dependencies`가 3D·2D·목록·상세·영향 결과의 공통 원본이다. 노드는 역할·출처·가정 기준 지표·구역 좌표를 가진다. 간선은 요청자→의존 대상, timeout, 재시도, 명시적 대체 유형을 가진다. 신규 의존은 순환이 없는 호출 그래프로 제공해야 한다.

`simulate()`는 순수 함수로 시간·주입·정책만 받아 결과를 계산한다. 렌더러와 무관하게 단위 검증할 수 있다. 실제 어댑터를 붙일 때는 읽기 전용 스냅샷을 별도 상태로 전달하고 SIMULATION 결과와 분리해야 한다. 현재 실측 어댑터는 없으며 화면에 실측 미연동을 명시한다. 정책은 실행 시 복사하여 완료 후 설정 변경이 과거 결과를 바꾸지 않게 한다.

## 계산 가정과 한계

- 요청자→의존 대상 화살표의 반대 방향으로만 장애 영향을 전파한다. 화면 진입점의 장애와 같은 JVM의 실행기 중단도 의존 간선으로 반영한다.
- 노드 정상 기준값, 대부분의 timeout, 전파 지연, 처리량, 4초 복구 램프는 명시적인 샘플이다. Jev 30초×2회, Hermes 90초는 저장소 기본 설정에 근거하지만 실제 배포값은 확인되지 않았다.
- 중단/단절/DB/외부 장애는 강도를 실패 비율로, 자원 부족/트래픽/적체는 `max(0, 강도−0.4)×0.85`로 근사한다. 지연은 유형별 가정값×강도로 계산한다. 트래픽 급증은 포화 효과의 근사이며 도착률·큐 길이를 예측하지 않는다.
- 의존 대상 지연이 timeout보다 크면 초과분/timeout을 0~1로 제한해 실패 비율로 적용한다. 여러 경로는 최악값을 취하여 동일 DB의 영향이 중복 합산되지 않게 한다.
- 처리량은 `기준값×(1−실패비율)/(1+추가지연/2000)`이다. 실측 TPS·사용자 수·금전 피해를 의미하지 않는다.
- 전파 관측은 간선의 timeout×시도 횟수만큼 지연된다. 복구 후에도 이미 대기 중인 경로가 늦게 영향을 보일 수 있다. 최대 105초의 추가 가상 관측창을 거친 뒤 완료한다. 일시정지는 모델 시계를 정지하며 백그라운드 탭은 시간을 누적하지 않는다.
- LOCAL Jev의 통신 오류만 Mock 전환을 모델링한다. 저신뢰 결과를 성공으로 바꾸지 않는다. Hermes Mock도 정상 AI 생성으로 표시하지 않는다. 대체 후에도 지연·품질 저하를 보존한다.
- Neo4j 런타임 장애의 자동 SQL 우회는 구현 사실이 아니다. SQL 전용 옵션은 처음부터 `NEO4J_URI=disabled`와 `GRAPH_REQUIRED=false`로 구성했다고 가정하는 비교 모드다. 실제 설정을 변경하지 않는다.
- 확인된 캐시·이중화 경로가 없어 기본 모델에 그 보호 효과를 부여하지 않는다. 검증된 구성이 생기면 간선과 계산 정책·테스트를 함께 추가해야 한다.
- 대표 검증은 PostgreSQL 연결 장애→API/BFF/화면→사용자 기능 영향→주입 해제→지연된 정상화다. 9가지 장애 유형은 적용 가능한 노드 종류로 제한된다.

## 검증 명령

```sh
cd frontend
npm ci
npm run typecheck
npm run test:unit
npm run build
npx playwright test --config=playwright.campus.config.ts
```

Node 22.18+ 또는 24를 사용한다 (순수 TypeScript 모델의 Node strip-types 테스트). 브라우저 테스트는 390×844·360×800 세로 화면에서 DB 주입→영향→승인→복구, WebGL 미지원 대체, 3D 로드, 키보드 닫기와 운영 API 쓰기 부재를 확인한다. 실 PostgreSQL/Neo4j 및 클라우드 배포 검증과 구분한다.

메모리가 작은 개발 PC에서는 `SCARE_LOW_MEMORY_BUILD=1`을 지정하면 빌드 작업자 1개와 Next.js의 Webpack 메모리 최적화를 사용한다. 런타임 기능은 바뀌지 않는다. 로컬 검증에서만 이 옵션과 `NODE_OPTIONS=--max-old-space-size=768`을 사용했다. 정상 배포에서는 기존 기본 작업자 수를 유지한다.

## 실제 연동을 위해 필요한 정보

1. 대상 배포 환경의 서비스/인스턴스 목록과 호출 관계, S-CARE 앱 구성과 관제 대상 금융 시스템의 범위 구분.
2. 읽기 전용 지표 API 또는 OpenTelemetry/Prometheus 스키마, 인증 방식, 샘플 응답, 갱신 주기. 비밀은 저장소에 넣지 않는다.
3. 실제 timeout·재시도·회로 차단·캐시 적중률·이중화·용량·대체 경로 조건.
4. `GRAPH_REQUIRED`, Neo4j 사용 여부, Jev/Hermes Provider 및 Mock 정책, 큐 작업/임대 설정.
5. 사용자 기능별 SLO, 실제 요청량의 집계 단위와 비식별 관측 근거. 검증 전에는 피해 사용자 수를 계산하지 않는다.
