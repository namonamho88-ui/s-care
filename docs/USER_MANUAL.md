# S-CARE — 사용자 매뉴얼

장애를 접수하고 AI 분석 결과를 읽는 방법

기준일: 2026-10-13. 모든 데이터는 가상입니다.

이 서비스는 가상 금융 IT 장애를 분석하고, 담당자 승인 후 가상 복구를 검증하는 시연 시스템입니다. 처음 사용하는 분은 아래 ‘첫 시연 따라 하기’부터 진행하세요.

## 1. 첫 시연 따라 하기

개인 아이디·비밀번호로 로그인합니다. 일반 사용자는 장애 등록·조회와 본인 담당 장애의 후기·예방 대책 작성이 가능합니다. 판단 검토·대응 승인·장애 종료·해결 절차 승인·평가·계정 관리는 관리자 권한이 필요하며 서버에서도 검사합니다.

장애를 등록하거나 열면 전용 처리 화면이 열립니다. 상단 스텝퍼의 6개 탭은 접수 → 분석·판단 확인 → 대응 승인 → 복구 검증 → 후기 검토·저장 → 장애 종료입니다. 노란색은 실제 현재 단계, 테두리는 보고 있는 탭, 체크는 완료를 뜻합니다. 메인 화면은 접수·현재 단계·처리 목록에 집중합니다. 상세 지표·Agent 현황은 관리자 메뉴 → 운영 현황에서 확인합니다.

전체 처리 %는 서버 상태와 저장 여부로 확인된 완료 단계 수 ÷ 6을 반올림한 값입니다. AI의 예상 소요 시간이나 개별 API 요청의 완료율이 아닙니다. 요청 중에는 요청명·서버 응답 대기·경과 시간이 별도로 표시됩니다. 종료 API가 성공하고 종료 상태를 확인해야 100%가 됩니다.

1. 처음에는 관리자로부터 아이디와 1회용 초대 코드를 받습니다. 로그인 화면의 ‘초대 활성화’에서 코드와 새 비밀번호(12~128자)를 입력합니다. 코드는 24시간 후 만료되며 재사용할 수 없습니다.
2. 다음부터는 ‘개인 계정’ 탭에서 아이디·비밀번호로 로그인합니다. ‘내 계정’에서 비밀번호를 변경하면 모든 기기에서 로그아웃됩니다. 분실 시 관리자에게 초대 재발급을 요청하세요.
3. ‘장애 직접 등록’에서 시연 모드 · 모의 판단, 구성요소, 가상 관측 내용을 입력합니다. 등록 시 새 장애가 DB에 저장됩니다. 일반 사용자에게 시나리오 자동 발생 버튼은 표시되지 않습니다.
4. 장애를 열어 판단·실시간 흐름을 확인합니다. ‘판단 확인’과 ‘승인 대기’는 관리자에게 요청합니다. 일반 사용자는 승인 API도 사용할 수 없습니다.
5. 현재 단계의 ‘지금 작성할 내용’에 필요한 입력만 보입니다. 저장·승인 후 다음 상태를 확인하면 다음 단계로 자동 이동합니다. 이전/예정 탭을 둘러볼 수 있고 ‘현재 단계로 돌아가기’를 누르면 자동 따라가기가 재개됩니다. 탭 이동만으로 승인·저장·종료가 실행되지는 않습니다.
6. 승인 후 ‘복구 완료’가 되면 본인에게 배정된 장애의 후기·예방 대책을 저장합니다. 다른 담당자의 장애는 조회만 가능합니다. 6단계에서 PDF/Excel을 다운로드하고 관리자에게 최종 종료를 요청합니다.

> 실제 AI 시연은 ‘실제 AI 모드 / Local jevos’를 선택합니다. Local은 Provider 이름이며, 현재 배포에서는 Railway CPU에서 실행됩니다.

## 로그인 없는 시연 접속

관리자가 별도 시연 환경·접속 장소·기간을 허용한 경우 로그인 없이 대시보드가 열리고 상단에 ‘시연모드 활성화’가 표시됩니다. 이때 데이터는 기존 계정 환경과 분리됩니다.

시연 참가자는 가상 장애 분석·승인·복구·종료와 지식 승인을 체험할 수 있습니다. 계정 관리, 비밀번호 변경, 외부 시스템 관리는 사용할 수 없습니다.

접속 허용과 AI 실행 방식은 별개입니다. DEMO는 모의 판단, REAL은 실제 모델 호출이며 결과의 실행 표시를 확인하세요. 시연 종료·세션 만료 시 로그인 화면으로 돌아갑니다.

## 대시보드에서 바로 시작하기

통합 관제 상단의 큰 접수 버튼부터 선택합니다. 알림 문자가 있으면 ‘문자 붙여넣기’, 문자 없이 이상 현상을 발견했다면 ‘장애 직접 등록’을 누릅니다. 접수 버튼을 여는 것만으로 장애를 생성하지 않습니다.

‘지금 처리할 장애’는 전체 조회 결과에서 종료·승인 거부를 제외하고, 내 확인이 필요한 항목 → 긴급도 → 최근 접수 순으로 표시합니다. 최근 이력이 모두 종료 상태여도 이전 미처리 장애를 찾을 수 있습니다. 각 항목에 현재 단계와 다음 행동을 표시하며, 클릭하면 기존 6단계 처리 화면이 열립니다.

목록은 10건씩 표시합니다. 상태 필터를 바꾸면 1페이지로 돌아가고, 완료·거부된 기록은 ‘전체 이력’에서 찾습니다. 이력 화면에서 지정한 유형·시스템·기간 조건은 대시보드에도 적용되므로 상단의 집계 필터 안내를 확인하세요.

관리자는 관리자 메뉴 → 운영 현황에서 지표·Agent 상세를 확인합니다. 시스템 영향도 메뉴는 모든 사용자가 조회할 수 있습니다. 사용 기술 설명은 화면 하단의 ‘기술별 역할 보기’ 또는 ‘사용 기술’ 메뉴에서 확인합니다. 장애 상세의 단계별 기술·실행 근거도 계속 제공됩니다.

| 필터 | 의미 |
| --- | --- |
| 전체 미종료 | 현재 조회 범위에서 종료·승인 거부 상태를 제외한 장애 |
| 내 확인 필요 | 관리자: 판단 확인·대응 승인·실패 확인·복구 후 마무리. 일반 사용자: 본인 담당 장애의 작성·검토가 필요한 후기 |
| 자동 진행 중 | 접수·분석·가상 복구 처리가 진행 중인 장애 |
| 복구 후 마무리 | 복구 검증 후 후기 저장 또는 관리자 종료를 기다리는 장애. 내 확인 필요와 중복될 수 있음 |

> 목록 필터와 항목 선택은 조회 기능입니다. 승인·재시도·종료는 상세 화면에서 권한에 맞는 버튼을 눌러야 실행됩니다.

## 발표용 요약 펼쳐 보기

장애를 열고 현재 단계 안내 아래의 ‘한눈에 보는 장애 대응’을 펼치세요. 발생 현상, 판단 결과, 영향 가능 대상 수와 지금 해야 할 일을 한곳에서 확인합니다.

가상 복구 검증 기록이 있으면 오류율·응답 시간·연결 시스템 상태의 조치 전후 값을 보여줍니다. 기록이 없거나 형식이 맞지 않으면 결과를 추정하지 않습니다. AI 분류 결과는 확정된 원인이 아니며, 판단 출처에서 실제 AI·모의 실행 여부를 확인하세요.

요약을 펼쳐 보는 것만으로 승인·저장·복구가 실행되지는 않습니다. 시스템 영향도는 연결 관계 분석, 해결 지식은 승인된 해결 절차, 관리자 메뉴 → AI 품질 관리는 AI 판단과 실행 규칙을 확인하는 메뉴입니다.

## 장애 강제 종료·삭제·복원

진행 중인 장애를 중단하거나 잘못 등록한 장애를 삭제하려면 관리자에게 요청하세요. 일반 사용자는 강제 종료·삭제·복원을 할 수 없습니다.

강제 종료는 복구 완료와 다릅니다. 삭제된 장애는 일반 목록에서 사라지고 관리자가 복원할 수 있도록 기록을 보존합니다. 복원해도 작업은 자동 재개되지 않습니다.

## 기술과 모델이 사용되는 지점 확인

왼쪽 ‘사용 기술’ 메뉴에서 6단계 기술 지도와 기술별 사용 지점·역할 표를 확인합니다. 각 업무 화면 하단의 ‘기술별 역할 보기’로도 이동할 수 있습니다. 일반 사용자와 관리자 모두 조회할 수 있습니다.

장애 상세 화면은 각 단계의 관련 기술을 표시합니다. ‘역할과 이 장애의 실행 근거 보기’를 펼치면 해당 장애에 저장된 Provider, 응답 모델, 실제 AI/Mock, 연결 실패 대체 사유, 그래프 엔진과 Agent 실행 기록을 확인합니다. 예정된 단계에는 실행 기록이 없을 수 있으며 이를 완료로 표시하지 않습니다.

Jev는 장애 유형·긴급도·담당 부서와 원인 후보 판단, Ontology는 의존 관계 영향 분석, A2A는 Agent 통신, Hermes는 승인 지식 검색과 해결 절차 초안을 담당합니다. Harness는 전 과정의 근거 검증·승인·실행 통제, MCP는 승인 후 가상 조치·지표 검증, PostgreSQL은 이력과 지식 저장을 맡습니다.

A2A의 6개 Agent가 모두 독립적인 LLM은 아닙니다. Diagnosis는 Jev, Knowledge는 Hermes를 사용하고 다른 Agent는 계획·그래프 결과·승인 지식·보고서를 내부 로직으로 구성합니다. 실제/Mock 판별은 선택한 실행 모드나 연결 배지가 아닌 각 응답의 기록을 기준으로 합니다.

Hermes의 응답 모델이 hermes-agent이면 서버 별칭입니다. 내부 OpenAI 모델명까지 확인된 것은 아닙니다. 지식 검색과 해결 절차 초안은 각각 실패·모의 판단으로 대체될 수 있어 따로 표시합니다. 해결 절차 승인·파일 게시 상태는 해결 지식에서 확인합니다.

## 문자 붙여넣기로 장애 등록

상단 ‘문자 붙여넣기’에서 배치 알림 또는 TMS 오류율 알림 한 건을 붙여넣습니다. 휴대폰에서도 같은 화면을 이용합니다. 휴대폰 자동 수신 기능은 포함하지 않습니다. 가상·비식별 문자만 입력하세요.

1. ‘내용 분석’을 누르면 서버 규칙으로 항목을 추출합니다. 이때는 DB에 장애를 만들거나 AI를 호출하지 않습니다. 화면의 가상 예시로 연습할 수 있습니다.
2. END_OK는 정상 종료로 표시하며 장애 등록에서 제외합니다. ABEND는 비정상 종료, DELAY_END는 종료 지연, TMS는 현재 오류율의 임계치 초과 여부를 확인합니다. 지원하지 않는 형식이나 누락·잘못된 값은 오류로 안내합니다.
3. 추출한 배치/IF 코드와 관측값을 확인하고 대상 구성요소를 선택합니다. 처음 입력한 코드는 자동 배정하지 않습니다. 같은 코드로 이전에 확인한 구성요소가 하나이면 추천하지만, 등록 전 다시 확인하세요.
4. 실제 AI 모드 또는 시연 모드 · 모의 판단을 선택하고 ‘등록 & 분석 시작’을 누릅니다. 저장 후 기존 6단계 처리 화면으로 이동합니다. 판단 근거가 부족하면 2단계에서 관리자 확인을 기다립니다.
5. 같은 알림을 다시 붙여넣으면 기존 장애를 엽니다. 요청 오류가 나도 입력은 유지되며 같은 문자 재요청은 중복 저장을 방지합니다.

> DELAY_END의 HH:mm은 종료기한이며 발생일시가 아닙니다. 업무일자·문자 발생일시(KST)·서버 등록 시각은 구분합니다. 생략된 배치명은 추정하지 않습니다. TMS 오류율 95.65%와 임계치 95%의 차이는 0.65%p입니다. 수신자 이름과 발신 기관명·원문 전체는 저장/AI 입력에서 제외하지만, 자유 텍스트에 포함된 개인정보까지 자동 익명화하는 기능은 아닙니다.

## 목록을 10건씩 보기

장애 이력, 해결 절차, 대응 매뉴얼, Harness 평가, 감사 로그, 등록 계정은 한 페이지에 최대 10건씩 표시합니다. 목록 상단과 하단의 처음·이전·페이지 번호·다음·마지막 버튼으로 이동하세요. 총 건수, 현재 표시 범위와 페이지 번호를 함께 표시합니다.

장애 제목/ID 검색이나 유형·시스템·기간 필터를 바꾸면 1페이지로 돌아갑니다. 각 목록의 페이지는 독립적으로 움직이며, 하단에서 페이지를 바꾸면 해당 목록 위로 이동합니다.

평가와 감사 로그는 서버에서 10건씩 조회하므로 오래된 기록도 마지막 페이지까지 볼 수 있습니다. 페이지 조회 실패 시 기존 결과와 오류가 표시되며 다시 조회할 수 있습니다. 새 평가를 실행하면 1페이지에서 진행 상황을 확인합니다. 일반 사용자의 조회·승인 권한은 바뀌지 않습니다.

## 2. 메뉴별로 무엇을 하나요?

| 메뉴 | 할 수 있는 일 | 어떤 때 보나요? |
| --- | --- | --- |
| 통합 관제 | 활성 장애·긴급 위험·복구시간·시스템 상태·실행 흐름 확인 | 현재 무슨 일이 진행 중인지 볼 때 |
| 온톨로지 | 전체 자산 의존 관계, 선택 장애의 영향 범위, 전체화면 탐색 | 장애가 어디까지 영향을 줄 수 있는지 볼 때 |
| 장애 이력 | 제목/ID·유형·시스템·기간으로 찾고 상세/보고서 열기 | 이전 장애와 조치 내역을 확인할 때 |
| 해결 지식 | 해결 절차·적용 조건·주의사항, 대응 매뉴얼 확인 | 비슷한 장애의 대응 방법을 찾을 때 |
| 사용 안내 | 사용자용/관리자용 매뉴얼과 인쇄용 파일 | 버튼의 역할이나 다음 단계가 궁금할 때 |
| 내 계정 | 역할·담당자 확인 및 비밀번호 변경 | 로그인 정보를 관리할 때 |
| 사용 기술 | 단계별 사용 기술·역할과 실제 AI/Mock 해석 방법을 확인합니다. | 조회 전용 안내입니다. 장애별 실행 근거는 장애 상세에서 확인합니다. |

## 3. 상태를 보면 다음 행동을 알 수 있어요

분석의 세부 진행은 ‘최근 실행’과 실행 타임라인에 표시됩니다. 실패·거부는 중단 상태로 표시되며 복구 완료로 처리하지 않습니다. 후기 초안을 보거나 수정만 한 상태는 미저장입니다. 저장 후 최종 검토와 관리자 종료가 필요합니다.

| 표시 상태 | 뜻 | 다음 행동 |
| --- | --- | --- |
| 접수 / 분석 중 | 장애 저장 후 Jev·Agent 분석 진행 | 타임라인 확인 |
| 판단 확인 | 신뢰도·근거가 부족하거나 판단이 불일치 | 관리자가 관측을 확인하고 확인 근거 입력 |
| 승인 대기 | 분석을 마쳤고 대응 허가를 기다림 | 관리자가 영향 범위와 복구 가이드를 검토해 승인/거부 |
| 복구 검증 | 승인 후 가상 지표를 변경하고 재측정 | 검증 결과를 기다림 |
| 복구 완료 | 가상 지표 검증 통과, 보고서와 해결 절차 초안 저장 | 본인 담당 장애의 후기·예방 대책 저장, 관리자에게 종료 요청 |
| 종료 | 조치 기록을 마감한 상태 | 보고서 조회/다운로드 |
| 실행 실패 | 연결 오류 등으로 흐름 중단 | 타임라인을 확인하고 관리자에게 문의 |
| 승인 거부 | 담당자가 대응을 허용하지 않음 | 사유 확인. 동일 장애를 자동 재개하지 않음 |

## 4. Jev와 여섯 Agent 결과 읽기

Jev는 관측 문장을 바탕으로 장애 유형, 심각도(P1/P2/P3), 담당 부서, 재발 의심을 판단합니다. P1은 서비스 불가, P2는 성능 저하, P3는 경미한 영향에 해당합니다.

‘실제 AI 모델 판단’과 ‘시뮬레이션 결과’를 먼저 구분하세요. 신뢰도는 모델의 판단 정도, 근거 충분도는 관측에 판단 근거가 얼마나 있는지를 나타냅니다. 높은 점수가 정답을 보장하지 않습니다.

Diagnosis가 제시한 원인은 ‘원인 후보’입니다. 최종 근본 원인으로 확정한 내용이 아닙니다. ‘원본 증적’에는 실제 요청과 응답이 저장돼 있습니다.

| Agent | 역할 |
| --- | --- |
| Incident | 장애 접수 및 업무 조정 |
| Diagnosis | 오류 분석과 원인 후보 제시 |
| Knowledge | 승인된 해결 절차·매뉴얼·유사 장애 검색 |
| Impact | 의존 관계와 영향 범위 분석 |
| Recovery | 대응 가이드와 복구 검증 |
| Report | 장애 보고서 구성 |

> Local jevos 연결 실패 시 MOCK_FALLBACK이 표시될 수 있습니다. 실제 AI가 성공한 결과로 해석하면 안 됩니다.

## 5. 온톨로지 그래프 사용법

분홍색은 장애 발생 지점, 노란색은 영향 가능성이 있는 자산입니다. 화살표 A → B는 A가 B를 사용한다는 뜻입니다. B에 장애가 생기면 B를 사용하는 A 쪽으로 역방향 탐색하며 최대 6단계까지 찾습니다.

영향 가능성은 연결 관계에 따른 범위입니다. 강조된 모든 자산에 실제 장애가 발생했다는 뜻은 아닙니다. 전체화면에서도 확대하지 않으면 많은 자산의 글씨는 작게 보일 수 있습니다.

1. ‘온톨로지’ 메뉴 또는 통합 관제의 의존 관계 패널을 엽니다.
2. 최근 장애 목록에서 상세를 열거나 온톨로지 메뉴의 분석 기준 장애를 선택하면 해당 장애의 영향 범위가 강조됩니다. 이미 저장된 분석을 조회하는 동작입니다.
3. ‘전체화면’을 누르면 현재 웹 화면 전체를 그래프로 사용합니다. ‘전체화면 닫기 · Esc’ 또는 Esc로 돌아옵니다.
4. ‘전체 자산’은 모든 자산을 표시하고, ‘영향 자산만’은 선택 장애의 영향 자산으로 좁힙니다. 장애 분석이 없으면 영향 필터를 사용할 수 없습니다.
5. 왼쪽 아래 +/−는 확대·축소, ‘전체 맞춤’ 네모 버튼은 현재 표시 중인 모든 노드가 보이도록 배율을 맞춥니다. 전체화면 버튼과 기능이 다릅니다.
6. 자산을 클릭하면 이름·종류·연결 수를 확인합니다. 빈 영역 드래그로 이동할 수 있습니다.

## 6. 장애 검색·보고서·직접 등록

1. ‘장애 이력’에서 제목 또는 장애 ID를 검색합니다. 유형·시스템·시작일·종료일도 조합할 수 있습니다.
2. 필터가 적용되면 통합 관제의 집계에도 적용됩니다. 화면의 필터 안내와 ‘집계 필터 초기화’로 전체 범위를 복원합니다.
3. 장애를 열고 ‘5. 후기 검토·저장’에서 조치 후기와 예방 대책을 입력한 후 반드시 ‘수정 내용 저장’을 누릅니다.
4. PDF/Excel은 ‘복구 완료’ 또는 ‘종료’ 상태에서 내려받아 사용합니다. 저장된 시드 이력에는 실제 AI 처리 근거이 없을 수 있습니다.
5. ‘장애 직접 등록’은 시나리오 선택 대신 가상 자산과 증상을 직접 입력하는 기능입니다. 실제 고객 정보·운영 로그·개인정보는 입력하지 않습니다.

## 7. Skill과 평가 결과 읽기

Skill은 적용 조건·점검 절차·해결 방법·주의사항을 가진 재사용 지식입니다. 대응 매뉴얼은 미리 준비된 절차이며, Skill은 장애 조치 후 초안으로 생성될 수도 있습니다.

승인 대기 초안은 검색에 쓰이지 않습니다. 승인됨은 DB 지식으로 사용 가능하다는 뜻이고 ‘Hermes Skill 파일 게시됨’은 별도 파일 게시도 완료됐다는 뜻입니다. 게시 실패와 승인 여부는 구분하세요.

‘API 서버 연결됨’은 Hermes 서버 통신 상태입니다. ‘최근 모델 응답 검증 완료’와 동일하지 않습니다. 서버 재시작 후 최근 응답 표시가 초기화돼도 기존 DB 증적은 남아 있습니다.

새 평가는 한국어 기술 관측 60건·경계 사례 20건·문자 형식 변형 20건을 사용합니다. 이전 47/50(94%)는 중복과 쉬운 단서가 있는 시연용 결과여서 모델 실력 근거로 쓰지 않습니다. 기존 영어 키워드 기준선, 실제 AI 호출 성적, Mock 대체, 오류와 검토 필요를 구분합니다. 이 평가도 가상 데이터이며 전문가 독립 라벨링·외부 운영 검증 전입니다.

## 운영 개선 기능 사용하기

장애 상세에서 ‘비슷한 과거 장애와 당시 조치 보기’를 펼치면 종료 이력과 공통 표현·동일 자산·유형을 비교합니다. 유사도 점수는 원인 확률이 아닙니다.

실시간 연결이 정상일 때 상세 화면은 이벤트로 갱신합니다. 연결 장애 시에만 30초 간격의 보완 조회를 하며, 목록은 최대 1분 간격입니다. 숨긴 탭은 조회를 멈추고 다시 열면 갱신합니다.

## 장애가 없어도 해결 지식 등록하기

1. 해결 지식 → 지식 직접 등록을 누릅니다. 제목·장애 유형·관련 시스템과 구성요소·발생 조건·주요 증상·점검 절차·해결 방법·주의사항을 입력합니다.
2. 임시 저장하면 등록자와 시각이 서버에서 기록됩니다. 본인 초안은 편집할 수 있으며 수정 사유와 변경 전후 내용이 남습니다.
3. 승인 요청을 누르면 승인 대기로 바뀝니다. 일반 사용자는 최종 승인할 수 없으며 관리자가 승인하거나 거부합니다.
4. 승인된 지식만 AI 검색·자산별 지식·장애별 추천에 표시됩니다. 유형 40점, 자산 35점, 시스템 20점, 유사 이력 5점의 일치 점수는 모델 확률이 아닙니다.

## 처리 중 영향 범위 확인하기

장애 상세 2단계 ‘분석·판단 확인’에서 저장된 온톨로지 결과를 확인합니다. 빨강은 발생 지점, 주황은 직접 영향 가능 자산, 노랑은 간접 영향 가능 자산, 회색은 범위 밖 자산입니다. 영향 가능성은 해당 자산에 실제 장애가 발생했다는 뜻이 아닙니다.

직접 영향/전체 영향, 영향 자산만 보기, 확대·축소, 전체화면을 사용할 수 있습니다. 노드를 누르면 기본 정보·연결된 구성요소·승인 지식·과거 장애·매뉴얼이 나옵니다.

3단계 대응 승인에서도 영향 가능 시스템 요약을 확인하고 전체 영향도로 이동할 수 있습니다. 결과가 없거나 분석이 실패하면 완료로 표시하지 않습니다. 이전 형식으로 저장된 결과는 직접/간접 구분이 미기록으로 표시됩니다.
