# 시연 대본

## 준비
최종 클라우드 시연 화면은 https://s-care-mu.vercel.app/ 이다. 클라우드 `ADMIN_TOKEN`으로 로그인한다. 이 PC의 값은 Git에서 제외된 `.env.cloud`에 있으며 화면 공유나 발표 자료에 토큰을 노출하지 않는다. Railway의 backend/jevos/hermes/neo4j가 정상 실행 중인지 확인하고 좌측 DB는 POSTGRESQL, 그래프는 NEO4J인지 확인한다. 실제 Hermes 생성은 OpenAI 키와 인터넷 연결이 필요하다.

로컬 개발 시 UI http://localhost:3100, backend `/api/health`, jevos `/health`, Hermes `http://127.0.0.1:8642/health`를 사용한다. 인터넷 연결 없이 재현해야 하는 발표는 PC에 이미지/모델을 받아 두고 DEMO를 선택한다. 클라우드 DEMO는 외부 모델을 호출하지 않지만 웹·DB 접근을 위한 인터넷은 필요하다.

## 1. 실제 AI 시연 (약 3분)
“모든 데이터는 가상입니다. Local Jev 모델은 Railway 컨테이너의 CPU에서, Hermes의 Skill 생성은 OpenAI에서 동작하고, 승인 이후에도 실제 운영 시스템을 변경하지 않습니다.”

실제 AI / Local jevos / SCN-01 → 가상 장애 발생.
“장애가 DB에 저장되고 Jev가 유형, 심각도, 담당 부서를 판단합니다. Provider와 모델, 실행 시간이 함께 남습니다.”

상세 & 승인 → 판단 증적 펼치기.
“보이는 확률은 실제 모델 응답입니다. 신뢰도나 근거가 부족하면 담당자가 확인할 때까지 멈춥니다.”

Ontology와 Agent 협업 탭.
“그래프는 Neo4j에서 의존 관계를 역방향으로 탐색합니다. 여섯 전문 Agent의 실제 HTTP 요청과 응답을 조회할 수 있습니다.”

승인 사유 입력 → 대응 승인.
“Harness가 승인 증적을 검사하고, MCP가 가상 지표를 변경합니다. 변경된 지표가 정상 범위인지 별도 검증한 후에만 복구 완료로 전환합니다.”

후기 & 보고서 → PDF/Excel → 장애 종료.
“보고서와 조치 이력이 PostgreSQL에 저장됐고, 해결 방법은 관리자 검토를 기다리는 Skill 초안이 됩니다.”

## 2. 판단 근거 부족 (약 1분)
시연 모드 · Mock → 장애 직접 등록 → 임의 가상 자산, 관측 `Something happened but no technical evidence`.
NEEDS_REVIEW를 확인한다. 분류/심각도/담당 부서와 확인 사유를 입력해 분석을 재개한다.
독립 원인 분석도 근거가 부족하면 추가 확인 단계가 생긴다. 원인 후보와 교차 검증 사유를 읽고 별도로 확인한다. 이 확인 이후에도 대응 승인이 여전히 필요함을 보여준다.

## 3. 연결 실패 대체 시연
별도 테스트 실행 환경에서 LOCAL_JEV_URL을 응답하지 않는 로컬 포트로 설정한다.
실제 AI / Local로 시작하면 두 번 시도 후 MOCK_FALLBACK이 표시된다.
“연결 실패를 실제 AI 성공처럼 표시하지 않습니다. 시뮬레이션 결과임이 화면·보고서·DB에 남습니다.”

## 4. 지식 승인과 자동 평가
지식 & Skill에서 신규 DRAFT의 적용 조건·절차·해결 방법·주의사항을 관측과 대조한 후 승인하거나 거부한다. 승인 전 검색에서 제외됨을 설명한다. 실제 클라우드 검증에서는 Hermes가 ‘최근 7일’을 ‘향후 7일’로 잘못 생성한 초안을 거부했고, Hermes 파일 카탈로그에도 게시되지 않았음을 확인했다. 실제 모델 생성 표시는 내용의 정확성을 보장하지 않는다. 현재 UI는 승인/거부를 지원하며 초안 수정·재생성은 후속 개선 범위다.
Harness & 평가에서 한국어 Mock 100건 또는 실제 Local 100건 평가를 실행한다.
“평가 정답은 모델에 전달하지 않습니다. 실제 일치율과 검토 필요 건수, 대체 실행 횟수를 각각 저장합니다.”

## 발표 전 확인
- 시연 시작 전에 서비스와 모델 준비를 확인한다. 모델이 꺼진 발표라면 DEMO를 명시적으로 선택한다.
- 현재 활성 장애는 최대 4건이다. 기존 승인 대기는 승인/거부하고 복구 완료 장애는 종료한다.
- 좁은 브라우저 패널에서도 메뉴를 사용할 수 있다. 발표 시 넓은 화면을 사용하면 그래프를 함께 볼 수 있다.
- PDF/Excel은 복구 완료/종료 상태에서 다운로드한다. 종료 전 후기와 재발 방지 대책을 저장한다.
- TypeSafe는 추후 API 키로 전환하는 구조다. Jev는 Local을 사용한다. Hermes 화면에서 API 연결, 실제 LLM 응답 검증, Mock 여부를 구분해서 설명한다.
- 승인된 Skill은 Hermes 파일 카탈로그로 게시된다. 승인 전에는 PostgreSQL DRAFT에만 저장되며 Agent 검색·Hermes 파일 게시에서 제외된다.
