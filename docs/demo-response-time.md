# 시연 응답 속도 및 입력 화면 개선 (2026-10-15)

## 운영 기록에서 확인한 병목

- 제보된 장애의 Jev 단계는 28,680ms. 모델 HTTP 요청 두 번에 27,776ms를 사용한 뒤 `LOCAL_JEV connection/timeout failure`로 `MOCK_FALLBACK`을 반환했다. 실제 추론 성공 기록이 아니다.
- Hermes 상위 단계는 23,245ms, 내부 Knowledge Agent는 9,351ms, 내부 Hermes HTTP 두 요청 합계는 3,171ms였다. 상위 A2A 시간과 모델 HTTP 시간을 합산하면 안 된다. 모델 추론과 네트워크만의 시간은 제공자가 보내지 않아 분리할 수 없다.
- 백엔드는 Railway 미국 동부, PostgreSQL은 Supabase 도쿄에 배치되어 있었다. 각 단계가 시작 이벤트, 종료 이벤트·체크포인트, 시작·종료 계측을 각각 별도 트랜잭션으로 저장하여 원격 DB 왕복과 동일 장애 잠금 대기를 늘렸다.
- 후기 저장 뒤 상세 조회뿐 아니라 전체 목록·대시보드 갱신도 기다려 화면의 요청 중 표시가 오래 남았다. 기본 펼침인 실행 내역과 모바일 고정 헤더가 실제 입력 양식을 밀어냈다.

## 변경

1. 사용자 선택에 따라 새 접수 기본값을 `DEMO`로 설정. Jev·Hermes는 기존 Mock 경로를 사용하며 실제 AI가 아님을 명시한다. REAL 선택, 실패 시 FALLBACK 표시는 유지한다. 기존 장애의 모드·결과를 다시 쓰지 않는다.
2. Harness 단계의 시작 이벤트와 계측 시작, 완료 이벤트·체크포인트와 계측 완료를 각각 한 트랜잭션에 저장한다. 단계당 네 트랜잭션을 두 개로 줄인다. 추론·A2A HTTP 호출은 트랜잭션 밖에서 실행한다.
3. 작업 임대·중단 검사, PostgreSQL 잠금, 완료 체크포인트, 승인·EvidencePolicy·MCP·감사를 유지한다. 완료 저장에 실패하면 완료 이벤트와 체크포인트를 함께 롤백하며 계측은 FAILED로 닫는다. 만료된 작업은 결과를 저장할 수 없다.
4. 단계별 내역은 기본 접힘. 현재 실행 중인 단계와 경과 시간은 접힌 상태에서도 표시하며 SSE 완료 반영을 유지한다.
5. 판단 확인·승인 사유·조치 후기 입력 양식에 강조 테두리를 적용하고 해당 양식으로 이동·초점 표시한다. 새로고침마다 입력 초점을 빼앗지 않는다. 모바일의 큰 헤더는 스크롤과 함께 올라가 입력 공간을 확보한다.
6. 후기·승인 등 처리 후 상세 상태를 먼저 반영하고 전체 목록 갱신은 백그라운드에서 수행한다. 실패한 갱신은 알림으로 표시한다.
7. 백엔드 단일 인스턴스를 싱가포르로 이동했다. Railway `asia-southeast1-eqsg3a` 1대 실행, `/api/health` UP 및 NEO4J 연결을 확인했다. 기존 PostgreSQL·Neo4j·모델 데이터는 이동하거나 수정하지 않았다. 기존 장애 217행(삭제 표시 3행 포함)의 전후 해시가 동일했다.

## 검증 방법과 해석

변경 전 기준은 배포된 main `9a7590aa77b2ccb474c1ae203ef9b10031fc99e3`이다. 동일한 가상 CPU 장애를 전후 DEMO Mock 10회, MOCK_FALLBACK 10회씩 실행한다. 메모리 H2, 루프백 A2A/MCP, 도달 불가 루프백 모델 주소만 사용한다. 각 JDBC 실행·커밋에 15ms의 합성 지연을 넣어 저장 왕복 차이를 비교한다. 트랜잭션 관리자와 JDBC가 동일한 DataSource를 쓰는지 검증한다. 이 지연은 운영 DB 지연의 측정치나 예측치가 아니다.

접수→승인 대기와 승인→가상 복구·보고서·지식 초안 저장 완료 시간을 합산한다. 사람의 승인·입력 시간은 제외한다. P95는 nearest-rank다. 운영 데이터에는 부하 테스트나 신규 장애 등록을 하지 않는다.

실제 AI 전후 성능·정확도는 미측정이다. 모델·질문·결과 스키마·근거 기준을 이번 변경으로 바꾸지 않았다. DEMO 기본값 변경은 정확도 개선이 아니라 명시적으로 선택한 모의 시연 경로이며 REAL 성능으로 보고하지 않는다.

## 반복 측정 결과

단위 ms. 합성 JDBC 지연 15ms 조건의 **격리 환경 결과이며 운영 전체 처리 시간으로 해석하지 않는다**. 새 기본값의 외부 모델 대기 제거 효과나 리전 이동 효과는 이 표에 포함되지 않는다. Fallback은 즉시 실패하는 루프백 주소를 사용하므로 운영의 28초 연결 실패를 재현한 값이 아니다.

| 결과 구분 | 전후 횟수 | 평균 전 → 후 | 중앙값 전 → 후 | P95 전 → 후 | 평균 감소 |
|---|---:|---:|---:|---:|---:|
| DEMO Mock | 각 10 | 7,657.5 → 6,744.9 | 7,587.9 → 6,684.4 | 8,098.3 → 7,217.2 | 11.9% |
| MOCK_FALLBACK | 각 10 | 7,591.4 → 6,662.5 | 7,566.4 → 6,650.0 | 7,728.2 → 6,760.0 | 12.2% |

40회 모두 `RESOURCE` 분류와 `RESOLVED` 도달을 확인했다. 이는 동일 가상 시나리오의 모의 결과 회귀 검증이며 실제 AI 정확도 점수가 아니다. 최종 코드의 트랜잭션 테스트 5개도 재통과했다. 원자료는 [demo-response-time.json](evidence/demo-response-time.json)에 저장했다.
