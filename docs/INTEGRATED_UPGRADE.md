# 통합 고도화 구현 계획

운영 배포는 별도 승인 전 수행하지 않는다. 기존 brain 스키마와 진행 중인 장애는 변경하지 않는다.

1. V11은 지식 메타데이터·자산 FK·시연 세션/설정 테이블만 추가한다. 기존 승인 이력과 AI 초안은 보존한다.
2. 전용 Railway 시연 백엔드는 `brain_demo_*` 스키마 및 별도 DB 사용자로 실행한다. 기존 백엔드와 동일한 코드를 사용하며 Vercel BFF가 계정 세션과 시연 세션을 다른 백엔드로 라우팅한다. 시연 허용은 AI 실행 모드와 별개다.
3. 시연 발급/요청은 서버 간 전용 키, 정확한 허용 Origin·Vercel 접속 IP 목록, 만료 시각으로 제한한다. DEMO_ADMIN은 업무 API만 허용한다. 계정/외부 게시/시연 설정 관리 접근은 차단한다. 관리자 설정은 기존 계정 인증을 검증한 BFF만 원격 시연 서버에 전달한다.
4. Neo4j는 시연 전용 노드 라벨과 관계만 사용한다. Hermes의 외부 Skill 게시를 시연 서버에서 비활성화한다. 승인된 DB 지식은 기존 Hermes 문맥 검색에 계속 전달한다.
5. 수동 지식은 등록자 소유 DRAFT → PENDING → 관리자 승인/거부로 진행한다. AI 초안의 기존 관리자 승인 흐름은 유지한다. 출처와 자산 관계, 추천 근거를 저장한다.
6. 온톨로지 결과에 직접/간접 영향과 시스템 목록을 저장하고 상세 2/3단계에 표시한다. 기존 결과는 저장된 affected와 현재 관계를 구분해서 표시한다.
7. H2/실제 PostgreSQL 격리·인증·회귀, Neo4j, BFF 접근 제한, UI·모바일·빌드를 검증하고 배포 검토 보고서를 작성한다.

Vercel IP 검증은 플랫폼이 덮어쓰는 X-Forwarded-For 단일 주소를 정확히 비교한다. Vercel 밖에서는 기본 차단하며, 로컬 개발은 명시적인 별도 설정으로만 허용한다. [공식 요청 헤더 문서](https://vercel.com/docs/headers/request-headers).
