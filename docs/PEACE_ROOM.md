# 평온의 방 — 오늘도 무사히

사이트 첫 화면 `/`과 `/peace-room`에서 자동으로 입장하는 공동 휴식 공간입니다. 닉네임이나 방 이름을 입력하지 않으며 모든 방문자는 `peace-together` 공용 정원에 모입니다. 기존 장애 대응·디지털 트윈은 `/operations`, 3D 워룸·금융 장애 훈련은 기존 경로에서 유지합니다. 이전 `/?view=twin`, `/?incident=…` 링크도 기존 업무 화면으로 연결합니다. 모든 공간과 행위는 가상의 3D 표현이며 운영 지표·승인·장애 확률을 변경하지 않습니다. 실제 접속자만 참가자로 표시합니다.

## 표현과 조작

- 천주교: 오른손으로 자신의 이마 → 가슴 → 왼쪽 어깨 → 오른쪽 어깨에 닿는 성호 동작. 별도로 십자가가 달린 묵주를 한 알씩 넘깁니다.
- 불교: 가슴 앞 합장과 가벼운 인사, 나무 염주 넘김을 구분합니다.
- 개신교: 손을 모으고 고개를 기울이는 묵상 기도 표현입니다. 모든 교단에 공통된 의례라고 정의하지 않습니다.
- 이슬람: 손바닥을 위로 들어 개인의 두아를 표현합니다. 정규 살라트의 순서·방향·시간을 재현하거나 예배를 완료했다고 표시하지 않습니다.
- 나만의 방식: 안정적으로 돌을 놓거나 균형 모드에서 놓을 위치를 선택합니다. 균형을 잃은 돌은 떨어지고, 기존 돌탑은 보존합니다. 최대 7개를 올릴 수 있으며 점수나 순위는 없습니다. 돌탑 초기화 버튼이 있고, 이동 중에는 서버가 기록한 위치에 돌탑이 남습니다. 다른 곳에서 돌을 다시 놓으면 자신의 돌탑을 그 자리로 옮깁니다.
- 종교 선택은 로컬 UI 상태입니다. 계정의 종교 프로필을 만들지 않습니다. 명시적으로 실행한 동작 종류와 진행 상태는 같은 방에 공개됩니다. 종교 이름을 참가자 배지로 표시하지 않습니다.

`성호 긋기`는 4초에 걸쳐 실행합니다. `묵주 한 알 넘기기`/`염주 한 알 넘기기` 버튼은 키보드 접근을 지원하며, 알 표시 영역을 오른쪽으로 밀어도 같은 동작이 실행됩니다. 동작 완료 이후 자동 반복이나 순위 계산은 없습니다. 움직임 감소 설정은 손의 대표 자세를 유지합니다.

기본 카메라는 정원 전체를 보여줍니다. `내 동작 크게 보기`는 사용자가 직접 선택하는 확대·추적 시점이며 `정원 전체 보기`로 돌아갑니다. 정원은 화면 전체를 차지하며, 하단의 돌탑 쌓기·묵주/염주·기도하기·소원 남기기·그냥 쉬기 메뉴에서 필요한 패널만 엽니다. 모바일 패널은 화면 높이의 38% 이내이며 닫으면 정원으로 돌아갑니다. 확대는 사용자의 선택으로만 실행합니다. 클릭 이동은 직선 이동이며 자동 경로 탐색은 아닙니다. 장애물 앞에서 1.5초 동안 진행하지 못하면 목적지를 취소하고 돌길·다리로 이동하도록 안내합니다. 퇴장·재입장과 연결 해제 시 이전 이동 입력을 비웁니다.

## 한옥 정원 구성

첨부 컨셉을 기준으로 U자 한옥 회랑, 곡면 기와, 목재 결·창살·커튼·방석, 중앙 나무, 회랑 뒤 수목, 화단, 돌길, 물길과 작은 다리, 등·물확을 실제 3D 지오메트리로 구성합니다. 생성 이미지로 3D 화면을 대체하지 않았습니다. 실시간 WebGL 장면으로, 참조 이미지의 실사 수준 재질·인물 모델을 그대로 재현한 것은 아닙니다.

안개·Bloom·DOF·CSS blur 없이 sRGB와 일정한 톤을 사용합니다. 반복되는 기와·목재·잎·돌은 InstancedMesh로 묶고 작은 자갈의 면 수와 그림자 비용을 줄입니다. 저사양 모드는 잎과 자갈의 수를 줄이고 Lambert 재질을 사용하며 동적 그림자를 끕니다. 일부 바닥 접촉 표현은 유지합니다. 그늘과 반사의 품질은 일반 모드와 다릅니다.

소원은 기존 방 채팅에 `🌿 소원 · `으로 전달하며 서버에 반영된 내용만 정원과 소원 목록에 표시합니다. 줄바꿈은 공백으로 정리합니다. 종교별 선택이나 소원을 계정 프로필로 별도 저장하지 않습니다. 최근 채팅 60개 범위와 임시 방 수명에 따르므로 영구 소원 게시판은 아닙니다.

## 실시간 통신

기존 게스트 세션 BFF와 Spring WebSocket을 사용합니다. 평온의 방 UI는 URL의 방 이름을 사용하지 않고 고정된 `peace-together` 방에 연결합니다. 예전 `?room=…` 공유 링크도 같은 정원으로 들어옵니다. 기존 `city-` 훈련방과 서버의 방별 격리 기능은 유지합니다. 명시적으로 나가기를 누르면 자동 재입장을 멈추고 다시 들어가기 버튼을 제공합니다. 공용 정원의 현재 정원은 20명이며 초과 시 오류와 재시도 안내를 표시합니다. 닉네임·외형은 서버에서 자동 배정하며 재접속 시 기존 게스트를 재사용합니다.

`peace-action`은 서버가 접속 세션의 행위자를 결정합니다. 허용 목록, 범위, 요청 중복, 빈도를 검증한 다음 `players[].ritual`을 갱신합니다. 캐릭터 이동과 행위는 기존 presence 채널에서 전달하며 장애 상태·훈련 점수·승인 버전을 변경하지 않습니다. 종교별 선택은 서버 계정이나 DB에 저장하지 않습니다. 재시작하면 임시 방 상태가 사라집니다. 연결이 끊긴 게스트의 재개 유예는 2분이며 게스트 세션은 최대 1시간입니다. 채팅은 방의 메모리에 최근 60개까지 유지합니다. 기존 단일 백엔드 인스턴스 구성을 전제로 합니다.

## 소리·진동

기본값은 모두 꺼짐입니다. 사용자가 켠 뒤 본인이 실행하고 서버가 수락한 행위에만 짧은 피드백을 줍니다. 재접속이나 다른 참가자의 동작으로 진동하지 않습니다. 접촉 소리는 로컬 Web Audio 합성음이며 외부 음원·유료 서비스·모델 호출을 사용하지 않습니다.

웹 Vibration API는 길이와 간격만 제어합니다. Android Chromium 계열에서 지원하며 Safari/iOS는 이 API를 지원하지 않습니다. 미지원 기기에는 진동 옵션을 비활성화하고 소리·화면 표현을 유지합니다. API 존재 여부와 성공 반환은 실제 모터 동작을 보증하지 않습니다. 자동화 테스트는 API 호출만 검증하며 물리 진동 검증은 실제 휴대폰에서 별도 수행해야 합니다.

## 환경과 실행

신규 환경변수·유료 서비스·DB 마이그레이션은 없습니다. 기존 `WAR_ROOM_ENABLED`, `WAR_ROOM_GATEWAY_KEY`, `WAR_ROOM_ALLOWED_ORIGINS`, `WAR_ROOM_WS_URL`, `BACKEND_URL` 설정을 재사용합니다. 일반 사용자의 운영 관리자 권한은 변경하지 않습니다.

- 프런트엔드: `cd frontend`, `npm run build`, `npm run start`
- 로컬 통합 검증: 먼저 backend의 `mvnw.cmd package`, frontend의 `npm run build`를 수행한 뒤 루트에서 `scripts/verify-peace-live.ps1` 실행. 임시 H2 환경을 사용합니다.
- 두 개의 독립 브라우저에서 사이트 첫 주소 `/`를 열면 별도 입력 없이 같은 정원으로 입장합니다. 서로 다른 동작을 실행한 뒤 상대 화면과 재접속 상태를 확인합니다.
- 디지털 트윈 메뉴와 기존 워룸 입구에도 평온의 방 링크가 있습니다.

## 동작 참고 자료

종파별 다양성을 존중하며 대표적인 선택지로 구현합니다. 자료의 기도문·음원·이미지는 복제하지 않습니다.

- [몬트리올 대교구 Family Prayer, 4쪽](https://www.diocesemontreal.org/sites/default/files/ressources/Foi%20catholique/prieres_courantes/Booklet%20-%20Family%20prayer.pdf): 오른손으로 이마, 가슴, 왼쪽·오른쪽 어깨를 짚는 순서.
- [Amaravati Buddhist Monastery Chanting Book, Añjali](https://cdn.amaravati.org/wp-content/uploads/2014/09/30/Chanting-Book-Vol-1-Web.pdf): 가슴 앞에 손바닥을 모으는 합장.
- [Egypt's Dar Al-Ifta: raising the hands in supplication](https://www.dar-alifta.org/ar/Fatwa/Details/17013/حكم-رفع-اليدين-عند-الدعاء-وكيفيته): 개인 두아의 손 표현과 방식의 다양성.
- [W3C Vibration implementation report](https://w3c.github.io/vibration/reports/implementation.html), [API specification](https://www.w3.org/TR/vibration/): 지원 범위와 진동 패턴 제약.

## 검증 기록

아래 2026-10-30 기록은 한옥 정원 재구성 이전 구현의 로컬 검증입니다. 재구성 이후 결과는 아래에 별도로 기록합니다. 해당 기록 시점에는 새 평온의 방을 운영에 배포하지 않았습니다. 자동 입장 및 운영 배포 결과는 별도 기록합니다.

| 검증 | 결과 |
| --- | --- |
| frontend `npm run build` | 최종 카메라·모바일 보완까지 성공 |
| frontend `npm run test:unit` | 65개 통과: 성호 접촉 순서/좌표, 움직임 감소, 방 이름 정규화 등 |
| backend `mvnw.cmd -q package` | 188개 중 186개 통과, 선택 실행 테스트 2개 제외 |
| 새 backend PeaceRoomIntegrationTest | 6개 모두 통과: 실제 WebSocket 공유, 다른 방 격리, 요청 중복·범위·빈도 검증, 재접속, 돌탑 앵커, 게스트 및 ACCOUNT ADMIN의 장애 명령 차단 |
| `scripts/verify-peace-live.ps1 -Regression` | 92개 통과: 평온의 방·기존 도시 미션·워룸·디지털 트윈·업무 UI 회귀 |
| 최종 모바일 보완 후 `scripts/verify-peace-live.ps1 -PeaceOnly` | 3개 다시 통과 |

평온의 방 브라우저 테스트는 독립 Chromium 컨텍스트 3개를 로컬 Spring WebSocket/H2 서버에 실제 연결합니다. 캐릭터 표시·이동·성호 단계·합장·두아·묵상·묵주·염주·공유 대화, 다른 방 격리, 요청 중복 제거, 재접속, 게스트 관리자 접근 차단을 확인했습니다. 1024px 태블릿과 390px 모바일 뷰포트, 브라우저 터치 입력, 수동 확대, 동작 버튼과 캐릭터의 동시 가시성도 확인했습니다.

진동은 브라우저 API를 계측해 본인 동작의 패턴, 다른 사람 동작/재접속에서 발생하지 않음, 미지원 시 비활성화를 확인했습니다. 실제 휴대폰의 물리 진동·음량/촉감, iPhone Safari 실기기, 5~10인 부하, PostgreSQL/Neo4j/Docker, 운영 클라우드에서는 이번 기능을 검증하지 않았습니다. 제외된 backend 테스트는 선택 실행 지연시간 벤치마크와 원격 Hermes bridge 게시 테스트입니다. 92개 UI 검증에는 기존 API 모의 응답 및 워크플로 로직 회귀 검사도 포함되며 모든 항목을 운영 서버 검증으로 해석하면 안 됩니다.

### 2026-10-31 한옥 정원 재구성 검증

- frontend 최종 `npm run build`: 성공. `npm run test:unit`: 65개 통과.
- backend `mvnw.cmd -q package`: 188개 중 186개 통과, 선택 실행 2개 제외. 한옥 나무·좌석·물길 충돌 범위를 반영했습니다. H2 기반 결과입니다.
- 독립 브라우저 3개 협업 검증 통과: 캐릭터 표시·이동·동작·대화·소원 공유, 다른 방 격리, 중복 요청, 재접속, 게스트 권한 분리, 재입장 이동 초기화. 피드백·염주·돌 낙하/초기화 검증도 통과했습니다. 최종 패널 수정 후 `scripts/verify-peace-live.ps1 -PeaceOnly -Grep mobile`의 2개 테스트도 통과했습니다(49.0초). 1024px 태블릿→390px 모바일 전환, 터치 이동, 새 모바일 세션의 확대·성호, 실제 PNG의 장면 디테일을 확인했습니다. 캡처를 직접 열어 캐릭터와 손이 가려지지 않는 것도 확인했습니다. 최종 검증에 테스트 전용 CSS 주입이나 브라우저 합성 비활성화 옵션은 없습니다.

검증 과정에서 모바일 확대 화면에 검은 사각형이 관측되었습니다. 같은 프레임의 원시 WebGL 캔버스는 정상이었고, 전체 페이지 캡처에만 패널 가림 영역이 위아래 반전된 형태로 나타났습니다. 닉네임 숨김·CSS 그림자 제거·별도 합성 레이어로도 재현됐습니다. alpha 지원 표면과 버퍼 유지 실험도 해결하지 못해 되돌렸습니다. 조작 패널에만 opacity 0.99를 적용해 불투명 영역 가림 최적화를 피하며, 3D 캔버스는 기존 불투명 렌더러와 clear alpha 1을 유지합니다. 화면 전체의 투명도·blur를 적용하거나 캡처를 합성하지 않았습니다. 회귀 검사는 실제 모바일 페이지 PNG에서 검은 영역뿐 아니라 단색 사각형으로 장면이 지워지지 않았는지도 확인합니다.

초기 다중 접속 실행은 300초 전체 제한을 넘겨 실패했으며 성공으로 집계하지 않았습니다. 최종 검증은 제한을 480초로 조정했습니다. 자동화 Chromium은 이 PC에서 SwiftShader 소프트웨어 WebGL을 사용하므로 이 실행 시간은 실제 사용자 기기의 FPS나 부하 성능 근거가 아닙니다. 실제 모바일 GPU·Safari·진동 모터 및 운영 클라우드는 미검증입니다. 기존 전체 92개 UI 회귀는 이전 구현의 기록이며, 한옥 재구성 이후 전체 92개를 다시 실행한 것은 아닙니다.

### 2026-10-31 공용 정원 자동 입장

사이트 `/`와 `/peace-room`에서 별도 폼 없이 `peace-together`에 입장합니다. 닉네임은 기존 서버가 자동 배정합니다. URL의 방 이름은 공용 정원 선택에 영향을 주지 않으며 나가기는 명시적으로 다시 들어갈 때까지 유지됩니다. 기존 업무 화면을 `/operations`로 이동했고 예전 view/incident 링크의 쿼리는 그대로 보존합니다.
