# 2차 구현 계획

## 이번 단계의 수용 기준

1. Diagnosis Agent가 관측을 바탕으로 별도의 Jev 질문을 실행하고 원인 후보·Provider·확률·근거·소요 시간을 기록한다. DEMO와 Local 장애 시 대체 결과를 구분한다.
2. Harness가 분류와 원인 후보의 일관성, 근거 충분도, 영향 분석의 발생 지점, 승인 Skill 존재 여부를 교차 확인한다. 판단 충돌은 담당자 확인으로 멈추며 검토 사유를 감사 로그에 보존한다.
3. 복구 가이드는 승인 Skill의 실제 절차를 사용하고 Report Agent는 저장된 Agent/승인/복구 검증 결과를 종합한다.
4. 공식 Hermes 대상과 연결 계약을 확인한 후 자체 저장소와 외부 Adapter를 선택하는 경로 및 외부 결과의 검토 절차를 구현한다. 대상이 확인되지 않은 상태에서 실제 연동 완료로 표시하지 않는다.
5. Docker Compose 구성 파싱, 이미지 빌드/실행, 전체 시연 검증을 각각 기록한다. Docker Engine이 없으면 구성 검증만 통과한 것으로 기록한다.
6. Provider·실패·판단 충돌 회귀 테스트와 실제 PostgreSQL/Neo4j/Local Jev 시연을 수행한다. 최종 결과와 필요한 사용자 입력을 기록한다.

## 확정된 연결 및 남은 환경 조건

- Hermes: Nous Research 공식 Agent, localhost:8642/v1. OpenAI API 키는 사용자가 로컬 .env에 입력했으며 실제 응답을 검증했다.
- Jev: 사용자 선택에 따라 Local jevos를 실제 검증한다. TypeSafe는 키를 나중에 설정할 수 있는 Adapter와 HTTP 계약 테스트를 유지한다.
- Docker Engine이 없는 이 PC에서는 Compose 구성 검증과 호스트 프로세스 통합 시연을 수행한다. 컨테이너 빌드/실행은 Docker 가능한 환경에서 추가 검증해야 한다.

## 변경 경계

기존 가상 데이터·시연 이력은 보존한다. 실제 운영 변경 도구는 추가하지 않는다.
분류 평가의 기존 50건 점수와 새 원인 분석 기능의 검증 결과를 혼합하지 않는다.
